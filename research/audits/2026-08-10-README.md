Three independent read-only audits (planner: plan coherence; reviewer: governance
and hack-channel integrity; researcher: literature soundness) of the whole
project at commit fc6c8f1, answering the owner's question: "is this project
actually right?"

## Unified verdict

**The bet is right; the current gate experiment is wrong.** The extern "C" +
dlsym evaluator direction is stronger than several published harnesses
(Kevin-32B, KernelBench, Sakana), and the project's invalidation discipline
(EXP-015'-A post-mortem) matches best practice. But EXP-018c as launched is
invalid on five independent counts, and the ledger has integrity holes that
would make the next result untrustworthy.

## Convergent findings (all three agents)

1. **018c cold-start violates do-not-repeat 2026-05-16** (EXP-001 family:
   raw base + sparse reward → zero variance → zero gradient). The revisit
   condition — p(valid candidate) ≥ ~0.05 — has never been measured.
2. **G=2 mathematically erases v3-symbol-shaped reward magnitudes** (any
   unequal pair → advantage ±1/√2); advertised TRLOO correction inactive
   under default loss_type=dapo.
3. **Launcher self-contradiction**: MAX_STEPS=25 vs pass criteria defined
   over steps 40–50; deep anti-hack scan script (criterion 3) does not exist;
   no save_steps/auto-resume.
4. **Unmarked verification run + master=null cold-start rule → a rerun today
   would be auto-promoted to master** (repeat of the EXP-015'-A shape).
5. **Open hack channels on the extern-C path**: reference-output scraping
   (same-process ref), stateful timing gaming (timed output never re-verified),
   tolerance/fast-math gaming (rtol=atol=1e-3 + default --use_fast_math),
   permanently fixed eval seeds. EXP-018a's 5/5 hacked-fixture replay
   acceptance was never executed or recorded.
6. **Ledger integrity**: ghost run slurm 7359525 (June 018c v1) unrecorded;
   "EXP-018d" identifier collision; campaign cites a nonexistent
   "2026-05-30 notes.md audit"; no evaluator version/hash field anywhere;
   comparability fields (task pool, init ckpt) missing from schema.
